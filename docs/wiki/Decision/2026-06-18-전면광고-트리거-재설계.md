# 2026-06-18 전면 광고 트리거 재설계 (저빈도 단일 → 마일스톤 경계 + 캡 완화)

> 장보기 완료 단일 트리거 + 하루 1회 캡 구조가 사실상 노출 0 에 수렴해 의미가 없던
> 문제를 해소한다. 포맷은 전면 유지하되, **트리거를 "마일스톤" 완료 경계(레시피 추가·
> 장보기 완료)로 넓히고**, **핵심 고빈도 행동(물건 추가)은 UX 부담이 커 트리거에서
> 제외**하며, **빈도 캡을 하루 1회 → 세션 기반(최소 간격 + 하루 N회)으로 완화**한다.

## 맥락

P2 에서 전면 광고를 도입할 때 트리거를 `shoppingSessionCompleted`(장보기 세션 완료)
하나로만 뒀다. 그런데 이 앱에서 장보기는 저빈도 행동이고, 그마저 "이번 세션 신규 체크
≥1 + 화면 이탈" 조건과 "하루 1회" 캡으로 더 좁혀져 노출이 거의 발생하지 않았다. 결과적으로
수익도 0, 광고의 존재 의미도 없었다. 또 빈도 캡 로직이 "같은 날이면 차단"을 먼저 검사해
30분 최소 간격 검사가 도달 불가능한 데드코드였다(`docs/follow-ups.md` 기존 관찰).

포맷 자체(전면 vs 배너/네이티브)를 바꾸는 방안도 검토했으나, 사용자가 **전면 포맷 유지 +
트리거 재배치·확장** 방향을 선택했다(배너 제외 기존 결정 유지).

## 결정

- **트리거 = "마일스톤" 완료 경계 2개.** `AdService.InterstitialTrigger` 는 저빈도이면서
  "의미 있는 작업을 끝낸 자연스러운 경계"(R6)인 것만 둔다.
  - `recipeAdded` — 새 레시피를 1개 **생성**하고 에디터를 닫는 시점(편집·삭제 제외).
  - `shoppingSessionCompleted` — 기존 장보기 세션 완료(유지).
- **핵심 고빈도 행동(물건 추가)은 트리거에서 제외.** 캡처 시트 저장 완료
  (`captureSessionCompleted`)는 노출 빈도를 가장 크게 올리지만, 물건 추가는 5초짜리
  초단타 핵심 루프라 그 직후 풀스크린 전면을 끼우면 일의 무게 대비 방해가 과하다. 짧은
  호흡 유틸의 "빠른 진입·이탈" 경험을 깨므로 의도적으로 트리거에 두지 않는다.
- **빈도 캡 완화** — "하루 1회"를 버리고 두 조건을 곱으로 적용한다(둘 다 만족해야 노출).
  - 마지막 노출 이후 **최소 간격 8분**(연속 노출 방지, 전면답게 넉넉히).
  - **하루(달력일) 최대 3회**(`UserDefaults` 누적 카운터 + 기준 날짜, 날짜 바뀌면 리셋).
  - 기존 데드코드(같은 날 차단 우선)를 제거해 최소 간격·하루 상한이 모두 실제로 동작한다.
- **모든 트리거는 동일 캡을 공유**한다(트리거별 차등 없음). 표시는 그대로 best-effort —
  미로드·캡 미통과·rootVC 부재 시 조용히 skip 하고 호출 흐름을 막지 않는다.
- **표시 시점 = 완료 후 화면이 닫힌 뒤**(`onDisappear`/세션 플래그). 시트·에디터가
  떠 있는 동안 present 하면 충돌하므로, 저장 시 세션 플래그만 세우고 닫힘 시점에 표시한다.

## 대안 / 폐기한 선택지

- **캡처(물건 추가) 트리거 포함** — 노출을 가장 크게 늘리지만 핵심 고빈도 루프를
  방해해 체감 불편이 크다고 보고 제외했다. 필요 시 "세션에 N개 이상 저장" 또는 "M번째
  세션마다" 같은 강한 게이팅을 얹어 재도입하는 방안은 열어 둔다.
- **배너/네이티브 도입(steady 노출)** — 짧은 호흡 유틸엔 전면보다 궁합이 좋지만, "전면+
  보상형만" 기존 결정을 뒤집는 비가역 방향이라 이번엔 보류(사용자 선택).
- **보상형 중심 전환** — 강제 노출 최소화 방향이나 이번 범위 밖.
- **트리거별 차등 캡** — 초기엔 단순한 단일 캡으로 시작하고, 실데이터로 필요 시 분화.

- 빌드: iOS 시뮬레이터 green, macOS(`CODE_SIGNING_ALLOWED=NO`) green, no-op 유지.
- 후속: 실기기에서 실제 노출 빈도·UX 체감 검증 후 캡 수치(8분/3회) 튜닝, 시트 닫힘 직후
  present 타이밍(드물게 실패 시 재시도) 확인, 출시 전 실광고 단위 ID 교체.

# 2026-06-18 CloudKit 가족공유 2차 가져오기

## 맥락

1차는 소유자가 현재 HomePin 데이터를 CloudKit root record 에 JSON 스냅샷으로 저장하고
`CKShare` 초대 UI를 띄우는 골격이었다. 2차는 초대를 수락한 참가자가 해당 공유 스냅샷을
`sharedCloudDatabase` 에서 읽어 로컬 SwiftData 로 가져오는 흐름을 닫는다.

## 결정

- 초대 수락 시 `CKShare.Metadata.hierarchicalRootRecordID` 를 `UserDefaults` 에 저장한다.
  - 저장값: root record name, zone name, owner name, accepted timestamp.
  - 초대 수락 자체는 기존처럼 `CKContainer.accept(_:)` 를 사용한다.
- Settings > Data 에 iOS 전용 `Import Shared Home Data` 버튼을 둔다.
  - 수락한 공유 root record 가 기록되어 있을 때만 활성화한다.
  - 가져오기는 자동 실행하지 않고 사용자가 명시적으로 누를 때만 수행한다.
- 가져오기는 `CKContainer.sharedCloudDatabase` 에서 저장된 root record 를 fetch 한다.
- root record 의 `dataJSON` 을 `BackupBundle` 로 decode 하고, schema version 을 확인한 뒤
  기존 `BackupUpsertEngine` 으로 로컬 SwiftData 에 upsert 한다.
- 성공하면 import 요약과 공유 record 의 `updatedAt` 시각을 alert 로 표시하고,
  마지막 가져오기 시각을 Settings 에 표시한다.

## 충돌 정책

2차는 단순 병합이다. `BackupUpsertEngine` 의 기존 정책을 그대로 따른다.

- 같은 UUID 는 shared snapshot 값으로 필드를 덮어쓴다.
- 없는 UUID 는 새로 생성한다.
- 공유 스냅샷에 없는 로컬 데이터 삭제는 하지 않는다.
- 사진은 1차 공유 payload 에서 제외했으므로 2차 가져오기에서도 복원되지 않는다.

## 의도적 제한

- 아직 실시간 양방향 동기화가 아니다.
- 참가자가 수정한 내용을 공유 record 로 다시 push 하지 않는다.
- 충돌 UI, 참가자 목록, 공유 해제/재초대, 사진 `CKAsset` 공유는 후속이다.
- 개발자 계정이 없으므로 실제 초대 수락 후 `sharedCloudDatabase` fetch 는 런타임 검증 전이다.

# 2026-06-18 CloudKit 가족공유 1차 스냅샷

## 맥락

가족공유는 Apple 가족 그룹 자동 연동이 아니라 CloudKit `CKShare` 초대 기반으로 처리해야
한다. 개발자 계정과 실제 CloudKit container 검증 전이라, 1차는 컴파일 가능한 초대 골격과
공유 데이터 포맷을 먼저 만든다.

## 결정

- Settings > Data 에 iOS 전용 `Share Home Data` 버튼을 둔다.
- 버튼은 `iCloud Sync` 가 켜진 상태에서만 동작한다. 꺼져 있거나 CloudKit 작업이 실패하면
  alert 로 사유를 표시한다.
- 공유 대상은 custom zone `HomePinFamilyHome` 의 root record
  `HomePinSharedHome/homepin-home-root` 로 둔다.
- root record 에 현재 SwiftData 상태를 `BackupBundle` JSON 스냅샷으로 저장한다.
  - 사진 원본은 1차 공유에서 제외한다(`photoFile = nil`).
  - `schemaVersion`, `updatedAt`, 엔티티 개수 메타를 함께 저장한다.
- 신규 공유는 `CKShare(rootRecord:)` 로 만들고 iOS `UICloudSharingController` 를 띄워
  초대·권한 관리를 Apple 기본 UI에 위임한다.
- 생성된 share record name 은 `UserDefaults` 에 저장하고, 이후 버튼을 누르면 기존 share 를
  재사용하면서 root snapshot 만 갱신한다.
- 초대 수락은 iOS app delegate 의
  `application(_:userDidAcceptCloudKitShareWith:)` 에서 `CKContainer.accept(_:)` 로 처리한다.

## 의도적 제한

- 1차는 **실시간 공동 편집**이 아니다. 공유 record 에 백업 JSON 스냅샷을 싣는 초대 골격이다.
- 참가자 쪽 `sharedCloudDatabase` 에서 공유 데이터를 읽어 로컬 SwiftData 로 병합하는 흐름은
  2차([[2026-06-18-CloudKit-가족공유-2차-가져오기]])에서 수동 가져오기로 추가했다.
- 충돌 해결, 참가자 목록 관리 UI, 공유 해제/소유권 이전, 사진 `CKAsset` 공유는 후속이다.
- 개발자 계정이 없으므로 실제 초대 발송·수락·서버 스키마 생성은 아직 검증하지 못했다.

- macOS compile build: green with `CODE_SIGNING_ALLOWED=NO`

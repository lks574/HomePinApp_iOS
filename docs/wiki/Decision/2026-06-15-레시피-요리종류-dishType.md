# 레시피 요리 종류(dishType) 필드 추가

## 맥락

[[Recipes]] 목록에는 분류 칩이 두 줄 있었다.

- 요리권(한식/일식/중식/양식/분식) → [[Recipe]] `cuisine` 필드와 연동된 실제 필터.
- 요리 종류(국·찌개/볶음/구이/조림/밥·면/반찬) → `AppOutlinedChip` 장식용, **모델
  필드도 없고 선택·필터도 안 됨.**

에디터([[RecipeEditor]])의 "분류"도 `cuisine` 만 다뤘다. 사용자가 요리 종류를
선택·필터하길 원해, 이를 데이터로 만들지 결정이 필요했다.

## 결정

[[Recipe]] 에 **`dishType: String?`** 필드를 추가한다(`cuisine` 과 같은 문자열 방식,
대칭).

- 값 집합(초기): `국·찌개`·`볶음`·`구이`·`조림`·`밥·면`·`반찬`. 목록 필터 칩과
  에디터 칩이 같은 프리셋을 쓴다.
- 목록: dish 칩을 `AppFilterChip` 선택형으로, `filteredRecipes` 가 cuisine·dishType
  둘 다로 AND 필터.
- 에디터: "분류" 카드를 요리권(cuisine) + 종류(dishType) 두 칩 줄로. 재탭 해제,
  빈 문자열 = 미선택. 기존 cuisine 자유 입력 TextField 는 제거(칩 단일 방식으로 통일).
- 시드: 10개 레시피에 dishType 배정.

## 근거 / 대안

- **문자열 vs enum**: `cuisine` 이 이미 문자열이라 일관성·유연성(시드/AI 확장) 위해
  문자열 유지. 값 검증이 필요해지면 후속에 enum 화 고려.
- **필드 없이 휴리스틱 필터**(제목 키워드 매칭): 부정확해 기각.
- **칩 제거**(기능 대신 정리): 사용자가 기능을 원해 기각.

## 영향

- SwiftData 옵셔널 필드 추가 → 라이트웨이트 마이그레이션(기존 레코드 `nil`). 앱은
  깨지지 않으나, 기존 시드 데이터에는 dishType 이 없으므로 값이 보이려면 재시드
  (DEBUG: 스토어 비우고 재설치)가 필요.
- 관련 코드: `Recipe.swift`, `SeedData.swift`, `RecipesView.swift`,
  `RecipeEditorModel.swift`/`RecipeEditorView.swift`, `RecipeDetailView.swift`(메타 표시).

# 2026-06-15 음성 입력(STT) 아키텍처

[[Capture]] 의 음성 입력(마이크)을 실제 받아쓰기로 연동하며 정한 비가역 결정
(마이크/음성 인식 권한 추가 + 음성 인식 API 채택).

## 맥락

추가/검색 시트([[Capture]])는 텍스트 + 음성 2-입력으로 설계됐고, 음성은 별도
인식 "엔진"이 아니라 **텍스트를 채우는 입력기**다(받아쓰기 결과를 활성 모드 필드에
주입, 텍스트 입력 경로는 항상 살아 있어 폴백 보장). 최소 사양은 iOS 26.5 / Swift 6.2
strict concurrency. 권한 키 추가(되돌리기 어려운 사용자 동의 표면)와 음성 인식 API
선택을 확정해야 했다.

## 결정

1. **권한 키**(`Project.swift` `infoPlist`): `NSMicrophoneUsageDescription`,
   `NSSpeechRecognitionUsageDescription` 추가. `.xcodeproj` 직접 편집 없이 Tuist
   manifest 단일 소스로 관리하고 `tuist generate` 로 재생성한다.
2. **인식 API**: iOS 26 의 온디바이스 `SpeechAnalyzer` + `SpeechTranscriber`(ko-KR)
   를 채택한다. `SpeechTranscriber(locale:preset: .progressiveTranscription)` 를
   `SpeechAnalyzer(modules:)` 로 구동하고, `AVAudioEngine` inputNode tap → PCM 버퍼를
   `AsyncStream<AnalyzerInput>` 로 흘려 보낸다. 결과 시퀀스(`transcriber.results`)는
   `result.isFinal` 로 volatile(부분)/finalized(최종)을 구분해 `transcript` 에 반영.
   한국어 모델 자산은 `AssetInventory.status(forModules:)` / `assetInstallationRequest`
   로 확인·설치하고, 미지원·미설치·권한 거부 시 상태를 정합하게 떨어뜨려 텍스트 폴백.
3. **권한 게이트**: 마이크는 `AVAudioApplication.requestRecordPermission`(iOS 17+),
   음성 인식은 `SFSpeechRecognizer.requestAuthorization` 를 그대로 재사용한다(인식
   경로가 아니라 권한 게이트로만).
4. **소유 (actor 경계 분리)**: UI 상태와 권한/오디오 처리를 두 타입으로 나눠
   `DictationEvent` 스트림을 경계로 통신한다(`Shared/Speech/`).
   - `@MainActor @Observable final class SpeechDictationViewModel` — UI 상태
     (`transcript`/`state`), `toggle()`/`reset()` 노출, **단일 세션 Task** 소유·cancel,
     이벤트→State 매핑·transcript 조립. View 는 이 타입만 `@State` 로 들고 호출부
     시그니처는 이전과 동일하다.
   - `final class SpeechDictationEngine` (`@unchecked Sendable`, 비-MainActor) — 권한·
     모델·`AVAudioEngine`·tap·변환·결과 소비. `start() -> AsyncThrowingStream<DictationEvent>`
     를 반환하고, teardown 은 스트림 `onTermination`(정상 완료/소비 Task cancel/에러)에
     연결한다. **엔진은 actor 로 강제하지 않는다** — `AVAudioEngine`/`AVAudioConverter`
     의 `Sendable` 경계가 애매하고, 시스템 콜백(권한 TCC·오디오 tap)을 MainActor 에서
     만들면 런타임 격리 트랩으로 크래시났던 이력이 있어서다. 대신 "엔진 객체는 `start()`
     가 만든 단일 소비 Task 안에서만 접근" 생명주기 규칙으로 동시성을 푼다(이 약속이
     `@unchecked Sendable` 의 근거). 시뮬레이터 분기는 엔진 capability 로 내려
     `unavailable(reason:)` 이벤트로 emit 한다.
   - `enum DictationEvent` — `preparing`/`recording`/`partialTranscript`/`finalTranscript`/
     `permissionDenied`/`unavailable(reason:)`. 권한 거부는 별도 케이스로 식별 가능하게
     두고 ViewModel 이 `.denied` 로, `unavailable` 은 `.unavailable(reason:)` 로 매핑한다
     (UI 가 거부="설정에서 허용" vs 불가용="텍스트로 입력" 문구를 분기하므로 합치지 않음).
   - 함께 해소한 버그: (a) 변환 없는 tap 경로에서 오디오 스레드 재사용 버퍼를 복사 없이
     yield 하던 데이터 레이스 → 새 `AVAudioPCMBuffer` 로 복사 후 yield. (b) `.preparing`
     중 재토글 시 고아 엔진 자원 누수 → ViewModel 단일 세션 Task + cancel→teardown 으로 차단.

## 대안 / 폐기한 선택지

- **`SFSpeechRecognizer` 직접 인식 경로** — 레거시 API. iOS 26 의 온디바이스
  `SpeechAnalyzer` 가 정확도·온디바이스 보장·결과 스트림이 우수해 인식 경로로는
  채택하지 않는다. 단 권한 요청 API(`requestAuthorization`)는 표준이라 재사용.
- **`DictationTranscriber` 모듈** — SDK 에 존재하나, 명시적 한국어 받아쓰기/모델
  자산 제어와 progressive 결과를 위해 `SpeechTranscriber` 를 택했다.
- **음성을 독립 파서/엔진으로 분리** — 텍스트·음성 입력 경로를 이원화하면 폴백·유지가
  복잡. 음성은 텍스트 필드를 채우는 입력기로만 두고 이후 AI 파서를 텍스트·음성 공용
  단일 경로로 재사용한다(후속).

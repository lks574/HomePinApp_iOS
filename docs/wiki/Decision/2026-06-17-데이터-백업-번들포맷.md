# 2026-06-17 데이터 백업 번들 포맷 — 디렉터리 패키지 + id upsert

> 전체 데이터 백업/가져오기([[DataTransfer]], `[screen-15]`)의 파일 포맷·복원 정책을 정한다.

## 맥락

기기 내부(SwiftData)에만 저장하는 로컬 앱이라 기기 교체·재설치 시 데이터를 옮길
수단이 없었다. 전체 데이터(9개 `@Model`: [[Space]]·[[Area]]·[[Spot]]·[[Item]]·
[[ItemCategory]]·[[Tag]]·[[Recipe]]·[[RecipeIngredient]]·[[ShoppingItem]])와
아이템 사진(`@Attribute(.externalStorage) Data`)을 하나의 파일로 내보내고, 다시
가져와 합칠 수 있어야 한다. 제약: 서버 없음, 외부 의존성 도입 최소화
(`Project.swift` `dependencies: []`).

## 결정

- **번들 포맷 = 디렉터리 패키지** `.homepinbackup`(exported UTType
  `com.sro.homepinappios.backup`, `com.apple.package` 준수). 내부 레이아웃:
  `data.json`(schemaVersion 메타 + 9 엔티티 Codable DTO) + `photos/<itemID>.dat`
  (아이템 사진 원본). 외부 의존성 없이 처리한다.
- **export 메커니즘 = 인메모리 `FileWrapper`(`FileDocument`)**. 디스크 임시
  디렉터리에 패키지를 쓰고 `FileWrapper(url:)` 로 감싸 `fileExporter` 에 넘기는 방식은
  쓰기 시 "파일이 이미 존재"(`NSFileWriteFileExistsError`) 에러를 내고 패키지가
  Files 에 안 나타났다. 그래서 임시 파일을 거치지 않고 `BackupDocument` 가 메모리
  데이터로 디렉터리 `FileWrapper`(`data.json` + `photos/`)를 **직접 구성**한다
  (`BackupArchive.makeExportPayload` → `BackupDocument.fileWrapper`).
- **import 메커니즘**: `fileImporter` 가 준 패키지 URL 을 `FileManager` 로 읽어
  `data.json`·`photos/` 를 파싱한다.
- **파일 모달 표시**: `fileExporter`/`fileImporter` 는 한 뷰에 여러 개를 쌓으면 일부만
  표시되므로(SwiftUI 한계), 각 모달을 별도 배경 앵커 뷰에 하나씩 부착한다.
- DTO 의 **관계는 객체 중첩 금지, 전부 UUID 참조**. `RecipeStep`(Codable struct)만
  `RecipeDTO` 안에 값배열로 인라인. 사진 바이너리는 DTO 에 넣지 않고 `photoFile`
  경로(`photos/<itemID>.dat`)만 참조.
- import 정책 = **id(UUID) 기준 병합/덮어쓰기(upsert)**. id 충돌 시 파일 내용으로
  필드를 덮어쓴다. 복원은 **2-pass**: pass-1 id 로 전 엔티티 fetch→있으면 필드
  갱신/없으면 insert, pass-2 UUID 참조로 관계 재연결.
- `schemaVersion`(현재 1) 가드: 번들 버전이 앱 지원 버전보다 높으면 거부.
- 행/엔티티 단위 실패는 스킵하고 결과를 요약한다.

## 대안 / 폐기한 선택지

- **ZIP 단일 파일(ZIPFoundation 등)** — 사용자 확정으로 불채택. 외부 의존성을
  들이지 않고 `FileManager` 만으로 디렉터리 패키지를 다루기로 했다.
- **단일 JSON 에 사진 base64 인라인** — 파일이 비대해지고 메모리 부담. 사진은 별도
  파일로 분리.
- **import 시 전체 삭제 후 재삽입(replace)** — 부분 병합·기기 간 머지가 불가능.
  id upsert 로 합치기를 택했다.

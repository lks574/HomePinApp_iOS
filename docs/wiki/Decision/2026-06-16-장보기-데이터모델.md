# 2026-06-16 장보기 데이터 모델

장보기(살 것) 체크리스트를 1차 도입한다. 수동 추가/체크(완료)/삭제 CRUD 를 기본으로
두고, 레시피 부족분은 원본 재료와 연결해 장보기 항목으로 추가한다. 재고 반영은 후속으로
분리한다.

## 결정

**신규 [[ShoppingItem]] `@Model` 을 도입한다.** 재고([[Item]])와 독립된 가벼운
체크리스트 엔티티다.

- 필드: `id`, `name`, `normalizedName`(`Item.normalize` 규약 재사용), `quantity: Int?`
  (옵셔널 — "나중에 정함"), `isChecked: Bool`, `createdAt`.
- 레시피 부족분 연동: `sourceIngredient: [[RecipeIngredient]]?`
  (`@Relationship(deleteRule: .nullify)`). [[RecipeDetail]] 에서 부족 주재료를 장보기에
  추가할 때 원본 재료를 연결한다. 재료 삭제 시 링크만 끊겨 장보기 항목은 온전히 남는다.
- 사용자 입력 데이터라 `name` 은 현지화 비대상(`Text(verbatim:)`).

## 대안 (기각)

| 대안 | 기각 사유 |
| --- | --- |
| `Item` 에 `needToBuy` 플래그 | 재고에 없는 "사야 할 것"을 재고 엔티티에 끼워 넣으면 위치(area 필수 규칙)·수량·유통기한 의미가 충돌. 살 것은 재고가 아니다. |
| `ShoppingList` 그룹 엔티티 | 1차엔 단일 목록뿐이라 그룹 계층은 과설계. 필요해지면 후속 도입. |

## 배치

- **홈([[Home]]) 장보기 요약 섹션** — 미완료 N개 요약(`shopping.toBuyCount`) + 상위
  3개 미리보기 카드. 홈이 이미 붐비므로 진입점+요약만 둔다.
- 전체 CRUD 는 [[Shopping]] 풀 화면(`ShoppingListView`)에서. 홈에서 값 기반
  `navigationDestination(for: ShoppingDestination.self)` 로 push.
- View ↔ SwiftData 직결: `@Query` 읽기, `modelContext` 로 insert/delete·`isChecked`
  토글(autosave). 단순 목록이라 별도 `@Observable` 모델을 두지 않는다(직결 우선 원칙).

## 마이그레이션

DEBUG 는 스키마 불일치 시 파괴적 리셋(`AppModelContainer`), 릴리스는 1.0 부터
`VersionedSchema` 도입 예정. 모델 단순 추가라 현 개발 단계에서 경량 변경으로 충분
(비가역 결정 아님). 상세: [[2026-06-12-swiftdata-마이그레이션-방침]].

## 구현 / 후속

- 구현됨: 레시피 부족분([[Recipe]] `missingIngredients`) → 장보기 자동 생성
  (`sourceIngredient` 연동). 부재료는 `missingIngredients` 에 포함되지 않아 대상에서 빠진다.
  같은 원본 재료나 같은 이름의 미완료 항목이 있으면 중복 생성하지 않는다.
- 후속: 장보기 완료 → 재고 반영(체크 시 `Item` 생성/수량 증가) 검토.

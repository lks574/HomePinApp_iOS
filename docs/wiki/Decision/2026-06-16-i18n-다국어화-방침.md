# 다국어(i18n) 다국어화 방침 — en/ko, 시스템 추종 기본 + 설정 수동 오버라이드

## 맥락

앱 전체 UI 텍스트가 한국어로 하드코딩돼 있었다(로컬라이즈 인프라 0,
`developmentRegion: "ko"`). 영어/한국어 두 언어를 지원하되, 기본/source 는 영어로,
기기 시스템 언어를 추종하게 하기로 했다.

> [!note] 결정 변경 (2026-06-16)
> 최초에는 "언어 선택 UI 없음(시스템 추종 전용)"으로 정했으나, 시스템 추종을 기본으로
> 두되 사용자가 **설정에서 언어를 수동 오버라이드**할 수 있게 확장했다. 사유: 시스템
> 언어와 다른 언어로 앱을 쓰고 싶은 사용자(예: ko 기기에서 영어 UI) 요구를 코스트 낮게
> 충족 — `.environment(\.locale)` 한 줄로 재시작 없이 즉시 전환되어 과설계가 아니다.

## 결정

- **언어**: 영어(en) + 한국어(ko). source/기본/폴백 = **영어(en)**. 기본은 시스템 언어
  추종이며, **설정 > 표시 > 언어**에서 시스템 따름 / English / 한국어로 수동
  오버라이드할 수 있다.
  - **언어 선택 UI**: `AppLanguagePreference`(`@AppStorage`, 테마 `AppThemePreference`
    선례와 동일 구조: `system`/`english`/`korean` + `title: LocalizedStringKey`). 루트
    `AppRootView` 에서 `preferredColorScheme` 과 같은 위치에 `.environment(\.locale,
    선택 locale)` 적용. `system` 은 환경 locale 을 강제하지 않아 SwiftUI 기본(시스템
    언어) 조회를 그대로 쓴다. en/ko 즉시 전환 런타임 확인 완료(ko-KR 시스템에서 english
    선택 시 English, english 시스템에서 korean 선택 시 Korean, 재시작 불필요).
- **UI 텍스트**: 단일 String Catalog `HomePinApp/Resources/Localizable.xcstrings`
  (source=en). SwiftUI `Text`/`Label`/`LocalizedStringKey` 자동 현지화.
  - 사용자 데이터(물건명·장소명·메모·레시피 내용 등)는 `Text(verbatim:)` 로 현지화 비대상.
  - 키 네이밍: **기본은 영문 원문 키**(예: `"Add Item"`). 인자·복수형·동음이의가
    필요하면 점 표기 의미 키(예: `recipe.minutes.%lld`, `count.items.%lld`,
    `place.delete.title.%@`)로 둔다. 복수형은 String Catalog plural variation,
    형식 인자는 `%lld`/`%@`(다중 인자는 `%1$lld %2$lld` 위치 인자).
  - `String` 타입으로 합성해 `Text`/`Picker` 에 넘기는 컴포넌트 라벨은
    `LocalizedStringKey` 파라미터로 바꾸거나(예: 버튼/섹션 타이틀/에디터 모델
    `title`·`saveTitle`), 호출부에서 `String(localized:)` 로 해소해 넘긴다.
- **권한 문구**: `HomePinApp/Resources/InfoPlist.xcstrings`(en/ko)로 현지화. `Project.swift`
  infoPlist 에는 영문 source 만 두고 `CFBundleDevelopmentRegion: "en"`,
  `CFBundleLocalizations: ["en","ko"]` 추가, `developmentRegion` 을 `"en"` 으로 바꿈.
- **시드 데이터(DEBUG)**: `AppModelContainer` 의 `#if DEBUG` 시드 게이트는 **그대로
  유지**(릴리스 동작 변경 없음). `SeedData.populate` 가 시스템 언어로 텍스트 세트를
  분기한다(`SeedText.current` = `Locale.current.language.languageCode == .korean ? .korean : .english`).
  시드 텍스트는 .xcstrings 가 아니라 **코드 내 en/ko 분기**(`SeedText`·`SeedText+Sets`).
  이유: 시드는 생성 시점 1회 고정 데이터라 런타임 언어 추종 대상이 아니다(이미 만든
  레코드를 언어 바꿨다고 갱신하지 않는다). 그래프 구조(항목 수·관계·임박일·매칭)는
  언어 무관 동일, 사람이 읽는 이름·문장만 분기. 설정 "전체 데이터 정리" 의 기본 Space
  복구도 같은 기준(`SeedText.current.space`).
- **cuisine/dishType**: 저장값(raw)은 **현행 한국어 그대로 유지**(SwiftData
  스키마/마이그레이션 변경 금지, 필터 동등 비교 키도 raw 유지 → 언어 전환에도 기존
  레시피 필터 안 깨짐). 목록 필터 칩·에디터 칩·상세 **표시 라벨만** 언어별로 매핑한다
  (`RecipeClassification.cuisineLabel/dishTypeLabel`, 프리셋 raw 키 목록도 단일 소스로
  제공). 시드의 cuisine/dishType 도 en/ko 모두 한국어 raw 키를 그대로 넣는다.

## 비대상(의도된 잔존)

- 사용자 입력 데이터(물건명·장소·메모·레시피 본문 등) — 현지화 안 함.
- 내부 로그·진단(`logger.error`/`assertionFailure`/`fatalError`) — UI 아님.
- NL 추출 프롬프트·`@Guide`(`NLRecipeParser`) — 한국어 추출 도메인이라 본 작업 비대상.
- STT 인식 `locale`(`SpeechDictationEngine` `Locale("ko-KR")`) 변경 — 본 작업 범위 밖
  (follow-up). 단 STT 권한·불가용·오류 **표시 문구**는 현지화 대상(엔진이
  `String(localized:)` 로 현지화한 reason 을 emit, 화면이 끼워 넣음).

## 검증

- 빌드 green(`xcodebuild ... -scheme HomePinApp`).
- 카탈로그가 `en.lproj`/`ko.lproj` 양쪽 `Localizable.strings`+`stringsdict`(복수형)로
  컴파일됨 확인. InfoPlist 권한 문구도 양 언어 컴파일.
- 시뮬레이터 `-AppleLanguages (en)`/`(ko)` 기동으로 UI 크롬·복수형·시드 언어 분기
  (en=Milk/Tofu/Eggs/My Home, ko=우유/두부/계란/우리집) 확인.

# 2026-06-18 area 생략 캡처 허용(미정리함) + 연속 입력 모드(여러 개 추가)

> 물건 추가의 두 마찰을 줄인다. ① 위치를 모르거나 나중에 정리하고 싶을 때 **구역(Area)
> 없이도 저장**(미정리함)할 수 있게 "생성 시 area 강제" 앱 규칙만 완화한다. ② 한 번에
> 여러 물건을 넣을 때 매번 에디터를 여닫지 않도록 **칩 staging 기반 연속 입력 모드**를
> 같은 캡처 시트 안에 둔다. 모두 **자동 저장 없이** 명시적 "추가" 에서만 insert 한다.

## 맥락

- `Item.area` 는 이미 옵셔널이고 nullify 보존을 위해 nil 이 합법이다([[2026-06-12-위치-물건-데이터모델]]).
  즉 "위치 미지정" 물건은 **스키마상 이미 가능**했고, 막던 것은 에디터의 앱 규칙
  (`ItemEditorModel.canSave` 의 `selectedArea != nil`) 뿐이었다.
- 단건 빠른 추가 파서(`ItemQuickAddParser`)와 단건 에디터 상태 소유 모델
  (`ItemEditorModel`)은 [[2026-06-15-에디터-상태-소유-패턴]]·
  `44eb...`(빠른 추가 파서 적용)에서 단건 전제로 설계됐다. AI/FoundationModels 기반
  NL 파서는 폐기됨([[2026-06-15-NL-추가-파서-FoundationModels]]).

## 결정

### ② area 생략 캡처 = (a) 앱 규칙 완화 (스키마·모델 무변경)

- `Item` 모델·스키마를 바꾸지 않는다. **신규 `@Model`·시스템 Area(가상 "미정리함"
  엔티티)를 만들지 않는다.** "미정리함" 은 단지 `area == nil` 인 물건의 표현일 뿐이다.
- `ItemEditorModel.canSave` 에서 `selectedArea != nil` 강제를 제거한다(이름·수량만
  충족하면 저장 가능). `save` create 경로는 이미 `area` 옵셔널을 그대로 넘긴다.
- area=nil 물건 노출은 **기존 경로 재사용**: 캡처 검색의 `wantsNoLocation`("위치미지정")
  필터가 이미 area·spot 모두 없는 물건을 추려 보여준다. PlaceDetail 의 "No Spot" 카드는
  area 가 지정된(spot 없는) 물건용이라 별개다. 새 노출 보일러플레이트는 추가하지 않는다.

### ① 연속 입력 모드 = 규칙 기반 멀티 파서 + 별도 staging 모델

- `ItemQuickAddParser` 에 단건 `parse` 를 건드리지 않고 멀티 래퍼
  `parse(multiline:areas:spots:)` 를 추가한다. **분절자는 쉼표(`,`·`、`)·줄바꿈만**
  이다(공백 분절 금지 — "유기농 우유" 보존). 조각마다 단건 `parse` 를 호출한다.
  AI/FoundationModels 부활 없음.
- 칩 staging 상태는 **신규 얇은 `@Observable` `ItemBulkAddModel` 이 소유**한다. 단건
  `ItemEditorModel` 을 다건으로 확장·오염시키지 않는다([[2026-06-15-에디터-상태-소유-패턴]]
  의 "화면당 모델 하나, 책임 분리" 연장).
- bulk insert 는 새 쓰기 경로지만 단건과 같은 불변식을 적용한다: 각 Item insert 시
  **name→normalizedName 동기화**, **`spot?.area ?? area` 위치 일관성**(bulk 는 spot 을
  수집하지 않으므로 사실상 칩 area 또는 세션 area).
- 세션 Area picker(생략 가능)를 두고 모든 칩의 기본 구역으로 적용하되, 칩 텍스트에서
  파서가 기존 Area 를 인식하면 그 칩만 override 한다.

### 자동 저장 없음 + 음성 자동 재시작 OFF

- 쉼표·줄바꿈·음성 무음 종료는 **칩 생성까지만**이다. 실제 insert 는 사용자가 명시적
  "추가" 버튼을 누를 때만 일어난다(명시적 쓰기 원칙 유지).
- 음성은 bulk 모드에서 `SpeechDictationViewModel` 의 무음 자동 종료(`.recording→.idle`)
  전이를 칩 경계로 쓴다: transcript→칩→reset. **자동 재시작은 OFF**(칩 1개 만들고 멈춤,
  사용자가 mic 재탭).

### 중복 = 차단 없는 인라인 경고

- bulk insert 시 staging 칩끼리 또는 기존 재고와 같은 `normalizedName` 충돌은
  **차단하지 않고 인라인 경고 배지로만** 노출한다. 단건 추가의 합치기
  confirmationDialog(검색-우선 캡처의 merge 다이얼로그)를 멀티에 연쇄 적용하지 않는다.
- 앱 로직 차원의 "이름 중복 방지"(유니크 제약 검토)는 별도 미결 항목으로 유지한다
  (`docs/follow-ups.md`) — 멀티 추가는 그와 독립적으로 경고만 한다.

## 영향

- 변경: `ItemQuickAddParser`(멀티 래퍼 추가), 신규 `ItemBulkAddModel`, `CaptureSheet`
  (bulk 모드 UI), `ItemEditorModel.canSave`(area 강제 완화).
- 무변경: `Item` 스키마/모델, nullify cascade, PlaceDetail 구조, 검색 랭킹.
- 화면 노트: [[Capture]], 모델 노트: [[Item]].

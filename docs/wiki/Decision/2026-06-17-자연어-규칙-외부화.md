# 2026-06-17 검색 자연어 규칙 외부화 — 번들 JSON 리소스

> 중앙 검색([[Capture]], `[screen-16]`)의 자연어 토큰화에 쓰는 조사 접미사·불용어·
> 의미 단어 사전을 코드 상수에서 번들 리소스로 분리한다.

## 맥락

`CaptureSearchQuery` 가 자연어 문장을 토큰화할 때 한국어 조사(`koreanSuffixes`)·
불용어(`stopwords`)·의미 단어(`semanticWords`) 3개 컬렉션을 코드 안 `static` 상수로
들고 있었다. 사전 보강은 검색 품질의 핵심인데, 코드 상수라 사전을 손볼 때마다 코드
변경·재컴파일이 필요했다.

## 결정

- 3개 컬렉션을 번들 리소스 `HomePinApp/Resources/SearchRules.json` 으로 외부화하고,
  `Shared/Search/SearchRules.swift`(`struct SearchRules: Decodable`)가 번들에서
  **1회 로드해 캐시**(`static let shared`)한다.
- `koreanSuffixes` 는 **순서 있는 배열**로 유지한다(긴 접미사부터 떼어내야 짧은
  접미사가 먼저 잘리는 오작동을 막는다). JSON 배열 순서를 그대로 쓴다.
- 리소스는 **번들 강제 포함**이며, 누락 시 빈 폴백으로 조용히 동작하지 않고
  `preconditionFailure` 로 즉시 드러낸다(규칙 누락이 검색 품질을 망가뜨리므로).
- 토큰화 호출 순서(suffix strip → stopword 제거 → semantic 제거)와 `Item.normalize`
  호출 순서는 외부화 전과 **동일**하게 유지(결과 회귀 0).
- 이번 외부화 대상은 위 3개만. 의미 플래그 후보 배열(`wantsExpiringSoon` 등의
  `containsAny` 후보)은 follow-up 으로 남긴다.

## 대안 / 폐기한 선택지

- **코드 상수 유지** — 사전 편집마다 코드 변경·재컴파일. 보강 빈도가 높아 부적합.
- **누락 시 빈 폴백** — 규칙 없이 조용히 전체 매칭/오토큰화로 빠질 위험. 강한 실패로 전환.
- **외부 의존성(형태소 분석기 등)** — 과한 무게. `Project.swift dependencies` 변경 금지
  원칙에 어긋남. 정규식/사전 기반 경량 규칙 유지.

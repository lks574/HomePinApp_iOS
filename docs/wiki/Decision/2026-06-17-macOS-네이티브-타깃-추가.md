# 2026-06-17 macOS 네이티브 타깃 추가 — 소스 공유 + `#if os` 흡수

> iOS 전용이던 HomePin 에 네이티브 macOS 앱 타깃을 더해 멀티플랫폼(iOS+macOS)으로
> 만든다. 소스·리소스는 한 벌로 공유하고 플랫폼 차이만 코드에서 분기한다.

## 맥락

기기 내부(SwiftData)에만 저장하는 로컬 앱이라 Mac 에서도 같은 데이터 흐름을 그대로
쓸 수 있다. 데스크톱에서 큰 화면·키보드로 재고/레시피를 다루고 싶다는 요구가 있어
macOS 지원을 추가한다. 제약: 외부 의존성 도입 최소화(`Project.swift`
`dependencies: []` 유지), 기존 iOS 동작·셸 UX 회귀 0.

## 결정

- **네이티브 macOS 타깃**을 택한다 — Mac Catalyst 도 Designed-for-iPad 도 아니다.
  - Catalyst 는 UIKit 호환 레이어를 끌고 들어와 SwiftUI·SwiftData 순정 코드를
    공유하려는 의도와 어긋나고, Designed-for-iPad 는 데스크톱 1급 경험이 아니다.
  - SwiftUI + SwiftData + Observation 은 cross-platform 이라 **소스 한 벌을 두
    네이티브 타깃이 공유**하고, AppKit/UIKit 가 갈리는 지점만 `#if os(macOS)` 로
    흡수하면 된다.
- **소스·리소스 공유**: `Project.swift` 에 타깃 두 개(`HomePinApp` iOS /
  `HomePinApp-macOS`)를 두고 둘 다 `sources: ["HomePinApp/Sources/**"]`,
  `resources: ["HomePinApp/Resources/**"]` 로 같은 경로를 가리킨다. 플랫폼 분기는
  코드 안 `#if os(macOS)` / `#if os(iOS)` 로 흡수하고, 셸(`RootTabView` 등)은
  재설계 없이 그대로 동작한다. (이미지 타입 차이는 [[2026-06-17-플랫폼-이미지-추상화]]
  의 `PlatformImage` 추상화로 분리.)
- **deployment target = `.macOS("26.0")`** (iOS 는 26.5 유지). iOS 26.5 / Swift 6.2
  최소 사양 정책과 같은 결로 최신 SwiftUI·SwiftData·Foundation Models·Speech API 를
  제약 없이 쓴다.
- **bundleId 분리**: iOS `com.sro.homepinappios`, macOS `com.sro.homepinappmac`.
  백업 번들 exported UTType 도 플랫폼별로 갈린다
  (`com.sro.homepinappios.backup` / `com.sro.homepinappmac.backup` — 양쪽 모두
  `.homepinbackup` 확장자·`com.apple.package` 준수, [[2026-06-17-데이터-백업-번들포맷]]).
- **카메라(`UIImagePickerController`)는 macOS 에 비노출**한다. 카메라 즉석 촬영 OCR
  ([[RecipeCapture]], `screen-13`)은 `UIImagePickerController` 기반이라 macOS 에
  대응 진입점이 없다. `CameraImagePicker` 전체를 `#if os(iOS)` 로 감싸고,
  `cameraCaptureCover` 헬퍼는 macOS 에서 no-op, 호출부는 `cameraAvailable`
  (macOS 에서 항상 false) 로 카메라 버튼 자체를 숨긴다. 사진 라이브러리(`PhotosPicker`)
  OCR 은 양 플랫폼 공통이라 macOS 에서도 OCR 입력이 가능하다.
- **권한·entitlements**:
  - macOS 는 sandbox 라 `Tuist/Support/HomePinApp-macOS.entitlements` 로 권한을
    명시한다 — `com.apple.security.app-sandbox`,
    `com.apple.security.files.user-selected.read-write`(백업 파일 Import/Export),
    `com.apple.security.device.audio-input`(STT 마이크).
  - **마이크·음성인식 usage description 은 양 플랫폼 공통**(STT)이라 공유 Info.plist
    (`sharedInfoPlist`)에 `NSMicrophoneUsageDescription`·
    `NSSpeechRecognitionUsageDescription` 으로 둔다.
  - **카메라·사진 권한키(`NSCameraUsageDescription`·`NSPhotoLibraryUsageDescription`)는
    iOS Info.plist 에만** 둔다(카메라 macOS 비노출, 사진은 PhotosPicker 가 별도 권한
    시트 없이 동작).
- **빌드/스킴**: 타깃별 스킴 분리(`automaticSchemesOptions` `targetSchemesGrouping:
  .notGrouped`). 한 스킴에 두 타깃을 묶으면(`.singleScheme`) macOS 데스티네이션
  빌드 시 iOS 타깃까지 끌려와 프로비저닝 서명 오류가 났다. 분리 후 `HomePinApp`(iOS)
  / `HomePinApp-macOS`(macOS) 스킴이 각각 노출되어 데스티네이션별로 해당 타깃만
  빌드된다.

## 대안 / 폐기한 선택지

- **Mac Catalyst** — UIKit 호환 레이어를 끌어와 SwiftUI/SwiftData 순정 공유를
  흐리고 데스크톱 1급 경험에 한계. 불채택.
- **Designed-for-iPad on Mac** — 별도 코드 없이 가장 싸지만 창/입력/메뉴 등
  데스크톱 경험이 아님. 불채택.
- **카메라 macOS 대응(AVFoundation 캡처)** — `UIImagePickerController` 대체로 macOS
  카메라 캡처를 새로 구현할 수 있으나, 본 작업 범위 밖. 사진 라이브러리 OCR 로
  충분하다고 보고 macOS 카메라는 비노출.

## 영향

- 영향받는 화면: [[RecipeCapture]](카메라 macOS 비노출, 사진 OCR 공통),
  [[Capture]](STT 양 플랫폼), [[DataTransfer]](파일 Import/Export sandbox 권한),
  [[Settings]].
- 가용성:
  - **STT**(iOS 26 `SpeechAnalyzer`+`SpeechTranscriber`) — 양 플랫폼. macOS 는
    `AVAudioSession` 개념이 없어 오디오 세션 설정을 `#if os(iOS)` 로 건너뛴다
    (audio-input entitlement 로 마이크 접근).
  - **OCR**(Apple Vision) — cross-platform. 입력 소스만 macOS 는 사진 라이브러리.
  - **FoundationModels**(온디바이스 NL 파서) — cross-platform 가용성 게이트
    (`SystemLanguageModel.default.availability`)로 동일 처리.
- `Project.swift` 타깃 2개·스킴 분리·entitlements 파일 추가(`tuist generate` 재실행
  필요). 셸(`RootTabView`)·네비게이션은 재설계 없이 그대로 동작(향후 macOS UX
  최적화는 범위 밖).
- 관련 결정: [[2026-06-17-플랫폼-이미지-추상화]].
- 후속(`docs/follow-ups.md`): 실기 런타임 검증(PhotosPicker OCR·파일 Import/Export·
  STT 권한/받아쓰기), sandbox 사진 entitlement 보정 필요 여부, macOS UX 최적화.

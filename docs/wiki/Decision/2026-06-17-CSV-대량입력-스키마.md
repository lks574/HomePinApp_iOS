# 2026-06-17 CSV 대량 입력 스키마 — 3-CSV, 이름 조회→생성

> CSV 대량 입력([[DataTransfer]], `[screen-15]`)의 파일 스키마·upsert 키·연결
> 규칙을 정한다.

## 맥락

기존 데이터(엑셀·다른 앱 export 등)를 한 번에 옮기고 싶다는 요구. 전체 백업
(JSON 번들)과 달리, 사람이 직접 작성·편집하기 쉬운 표 형식이 필요하다. 대상은
사용자 확정으로 **[[Item]]·[[Recipe]] 두 가지만**.

## 결정

- **3개 CSV 파일**로 나눈다: `items.csv`, `recipes.csv`, `recipe_ingredients.csv`.
  재료는 별도 id 없이 **`recipeTitle` 로 레시피와 연결**한다(재료 import 는 레시피
  import 이후 실행, 매칭 레시피 없으면 행 스킵).
- **upsert 키**: `id` 컬럼 있으면 id, 없으면 `normalizedName`([[Item]]) /
  `title`([[Recipe]]).
- **area/spot/category/tags 는 이름 조회→없으면 생성**. 한 import 안에서 같은
  이름을 다시 만들지 않도록 조회 캐시를 둔다. area 는 `space`+`area` 이름 조합으로,
  spot 은 `area`+`spot` 조합으로 식별한다. tags 는 세미콜론(`;`) 구분.
- 파서는 **RFC4180 최소 자체 구현**(따옴표·콤마·개행 이스케이프, CRLF/LF). 외부
  의존성 없음. 각 CSV 의 **템플릿 export**(헤더 + 예시 행) 제공.
- 엔진 강제 규칙(백업 엔진과 동일): `name` 설정 시 `normalizedName` 동반 갱신
  (`Item.normalize`), 불변식 `spot != nil → item.area == spot.area`.
- 행 단위 실패는 스킵하고 사유를 결과 요약에 남긴다.

## 대안 / 폐기한 선택지

- **단일 CSV 에 모든 엔티티** — 컬럼이 폭증하고 한 행이 무엇을 뜻하는지 모호.
  엔티티별 파일로 분리.
- **재료를 recipeID(UUID)로 연결** — 사람이 직접 적기 어렵다. 사람이 아는
  `recipeTitle` 로 연결.
- **area/spot/category/tags 도 id 필수** — 신규 데이터 입력 진입장벽이 높다. 이름
  조회→없으면 생성으로 완화.

# AI 적용 후보 (온디바이스 Foundation Models)

우리 앱(위치 핀 + 식품 재고 + 레시피 소비 루프)에 **Apple Foundation Models**
(온디바이스·무료·오프라인, `@Generable` 구조화 출력)를 넣기 좋은 지점 모음.
제품 방향은 [[제품-방향-재고-레시피-AI]], 음성 입력 경로는
[[2026-06-15-음성입력-STT-아키텍처]] 참조. **방향 브레인스토밍**이며 결정/아키텍처가
아니다(착수 시 화면·결정 노트로 구체화).

## 적합성 기준 (소형 온디바이스 모델)

- **잘함**: 분류·추출·구조화(`@Generable`)·의미 매칭·요약·짧은 생성.
- **못함**: 긴 추론·정확한 사실 검색·영양/칼로리/가격 계산. → 넣으려면 "참고용" 라벨 필수.
- **공통 규칙**(제품 방향에서 계승): 기존 위치/카테고리에 **grounding**, **확인
  드래프트 단계 필수**, **없으면 생성 / 있으면 기존 매칭**, **여러 개 배열 파싱**,
  **수동(텍스트) 폴백 항상 살아있음**.

## 이미 계획에 있는 것 (재확인)

- **NL 자연어 추가 파싱** — 문장 → `[[Item]]` 구조화 드래프트. `docs/next-task.md` #1,
  `[[Capture]]`. **공용 단일 파서 엔진** — 아래 다수가 이 엔진/스키마를 재사용한다.
- **자동 분류·태깅** — 이름 → `[[ItemCategory]]`·`[[Tag]]` 추천.
- **자연어 검색** — "곧 상하는 냉동실 고기" → `#Predicate` 변환.
- **find/add 의도 자동 판별** — 한 입력에서 찾기 vs 추가 분기.
- **레시피 추천** — 임박 재료 → `[[Recipe]]` 매칭 (킬러 루프).

## 신규 후보

### A. 입력 마찰 줄이기 (`@Generable` 직결)

1. **영수증/사진 → 대량 항목 추출** — 마트 영수증을 VisionKit OCR → 텍스트를
   Foundation Models 로 `[[Item]]` **배열** 파싱(한 번에 다건 입력). 재고 등록 마찰의
   최대 해소. 단 OCR 파이프라인이 필요해 스코프 큼(비전은 별도, 모델은 텍스트 전용).
2. **레시피 텍스트 붙여넣기 → 구조화** — 웹/메모의 레시피 한 덩어리 → `[[Recipe]]`
   (재료 배열·단계·dishType) 자동 채움. `[[RecipeEditor]]` 입력 마찰↓. 구조화 출력에 딱.
3. **스마트 위치/분류 추천** — 새 물건 등록 시 이름 → 둘 곳 추천(우유→냉장고).
   기존 `[[Space]]`/`[[Area]]`/`[[Spot]]`·카테고리에 grounding. NL 추가의 "있으면매핑" 확장.

### B. 킬러 루프 강화 (소비)

4. **부족분 → 장보기 리스트 자동 생성** — `[[Recipe]]` 선택 시 부족 재료 추출 + 유사명
   묶기. (제품 방향의 "부족분 쇼핑 리스트" 능동화.)
5. **"지금 만들 수 있나?" 요약** — 레시피 ↔ 재고 매칭을 자연어 한 줄로(보유/부족/임박
   활용도). `[[RecipeDetail]]`.

### C. 재고 위생 (중복·정리)

6. **중복/유사 항목 병합 제안** — "냉동실 vs 냉동고", "소고기 vs 쇠고기" 의미 dedup.
   소형 모델 강점, 제안만 하니 저위험. 제품 방향의 "유사 중복 방지"를 능동 기능으로.
7. **미분류 항목 일괄 분류** — 온보딩/정리 시 카테고리·태그 없는 항목 배치 추천.

### D. 조회·답변 (음성 루프 완성)

8. **자연어 위치 질의응답** — "참치캔 어디 있어?" → 위치 경로 답변 (+선택 TTS). 방금
   만든 STT([[Capture]])와 직접 연결. 제품 방향의 "말로 찾고" 실체화.
9. **대시보드 주간 요약** — "임박 5개, 한 달째 안 쓴 재고 3개" `[[Home]]` 카드 요약문.
   요약은 소형 모델 강점.

## 우선순위 제안

- **지금 바로**: **NL 추가 파서 엔진**(계획 #1) 먼저 — 단일 파서라 6·7·8이 같은
  엔진/스키마를 재사용. 한 번 만들면 파생이 싸다.
- **빠른 후속 高임팩트**: 6(중복 병합 제안) — 작고 저위험, 재고 품질 직결.
- **레시피 축**: 2(레시피 구조화) + 레시피 추천 묶음.
- **나중/스코프 큼**: 1(영수증 OCR), 8(TTS 답변).

## 선행 결정 (미정)

- Foundation Models 채택 **ADR 미작성** — 착수 전 `Decision/` 노트 필요(프레임워크
  채택 + `@Generable` 스키마 = 데이터 모델 인접 결정).
- **기기 게이팅** — Apple Intelligence 지원 기기 + iOS 26 필요. `SystemLanguageModel`
  가용성 분기 + 미지원 폴백(수동 입력). `docs/next-task.md` #5 와 연결.
